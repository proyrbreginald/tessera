## 写作约定

- **事实必须带依据**：引脚/时钟/偏移等给出来源（原理图页码、数据手册章节、实测记录）。
- **未确认项标 🟡**：不得当事实使用；`xtask check-gaps` 会清点实现侧的未实现项。
- **不写"将会实现"**：只写"当前是什么"与"缺口在哪"，避免文档变成愿望清单。
- **目标架构必须标注状态**：capsule 方向是已冻结的架构决策。`sdk`（`Capsule<C>`/`CapsuleSet`/`Product`）
  与产品组合根外提（S1，`product`）已落地；S2 上下文能力对象化、S3 基础 capsule 外提与
  仓库外插件门禁**尚未实现**。文档必须区分“当前已具备”与“目标形态 / 尚未实现”。
- **可变的测量值不写进文档**（测试数、覆盖率、映像字节数）：用 `cargo xtask context` 取。
