# 需求规格（平台底座）

> **本文件是需求的唯一真源。** 追溯关系不手写：`cargo xtask gate trace` 会扫描源码，
> 生成 [`需求追溯矩阵.md`](需求追溯矩阵.md)，并对**未被任何代码/测试引用**的需求报错。
>
> 判定约定：需求编号出现在源码里即可 —— 测试函数名用下划线形式（如 `fn rt_1_...`），
> 或注释里写出原文（如 `// 平台需求 RT-1`）。"需求有没有被落实"因此是**可执行**的
> 问题，而不是靠审阅者记忆。
>
> 本底座**不包含任何具体业务语义**（那是接入方自己的 crate）。这里定义的是
> "任何上层业务都依赖的平台能力与保证"。七条主线：
> **实时性、性能、可维护性、可发展性、可调试性、安全性、可测试性**。
>
> **架构方向（不是新增需求编号）**：平台采用静态 capsule 化内核（[架构与实现](../架构与实现.md)）。
> 业务是仓库外的可信 capsule，编译期静态组合；不做运行期热替换，也不把 safe capsule
> 当成安全隔离。`sdk`/`Capsule` trait/产品组合根外提（S1）已落地；S2/S3 尚未实现，
> 因此本文件不新增 capsule 需求编号，避免把规划混进当前追溯口径。

## 实时性（RT）

| 编号 | 需求 | 验收/机制（可执行判据在哪） |
|------|------|------------------------------|
| RT-1 | 关中断窗口必须有预算、必须实测、且**只能**经测量入口进入 | `realtime::BUDGET_IRQ_OFF_MICROS` 与编译期断言（`primitives::budget`）；`cargo xtask gate critical` 拒绝绕过 `board_support::rt::measured_cs` 的临界区 |
| RT-2 | 每条 ISR 与任务步长必须有实测统计与机器判据 | `realtime` 的 `Span`/`SpanStats`/`RtMetrics::check`；心跳（`beat on` 开启）`rt=ok|VIOLATION|none`（三态）；真机抓包与 `cargo xtask monitor` 判读 |
| RT-3 | 长操作（Flash 擦写、压缩、大扫描）**不得**在关中断或 ISR 中执行 | 文件系统写队列（生产者投递 + `idle` 属主执行，`filesystem::write_queue`）；`board_support::fs::with_fs` 的"只读、失败即返回 `None`"契约 |
| RT-4 | 时基必须 64 位、回绕安全、可自证漂移 | `primitives::time::Timepoint` **不实现 `PartialOrd`**；`board-support` 的 PIT 链式时基；`cargo xtask monitor` 的 uptime 漂移判据（±2%） |

## 性能（PF）

| 编号 | 需求 | 验收/机制 |
|------|------|-----------|
| PF-1 | 关键路径必须有真机实测事实（Flash 读吞吐、FS 挂载、SDRAM 自检） | 启动横幅的 `flash rd :`/`fs mount`/`sdram` 实测行；`cargo xtask bytecheck` 逐字节校验（原性能基线门禁已移除） |
| PF-2 | 内存必须**静态可知**：无通用堆、固定块池、失败是一个值 | `block-pool` 的位图策略（无碎片/不合并/不切分）；BSP 的两段固定块静态池；分配失败返回空指针、绝不 panic |
| PF-3 | 代码体积与内存放置必须有上限门禁 | `cargo xtask gate memory`（`.text` 在 ITCM 且不超预算、`.stack` 在 DTCM）；`check-size`（映像 < 1 MiB）；`check-code-placement`（`.xip` 白名单） |

## 可维护性（MT）

| 编号 | 需求 | 验收/机制 |
|------|------|-----------|
| MT-1 | 分层必须是**编译期事实**：纯逻辑 crate 的依赖闭包里不得出现硬件 crate | `cargo xtask gate layering`（含传递闭包与 dev-dependencies；名单唯一来源是 `PURE_CRATES`） |
| MT-2 | 文档中的**常量类数字**必须与代码/门禁一致，文档不得成为第二份事实来源 | `cargo xtask gate docs`（成员/纯逻辑 crate 数、静态门禁条数、unsafe 预算、缺口数）；分区表由 `flash-layout` 一处定义、三方引用 |
| MT-3 | 未实现必须**显式**：禁止 `todo!()`/假装成功，缺口可被机械清点 | `check-style`（无 `todo!`/`unimplemented!`）；`check-gaps` 清点全部 `GAP(Px)`；错误变体 `NotImplemented`/`Rejected` |
| MT-4 | 每个 crate 必须有模块文档与**统一 lint 头**；纯逻辑 crate 禁止 `unsafe`（编译期事实） | `check-lint-headers`（`forbid(unsafe_code)` + `clippy::unwrap_used`/`indexing_slicing`）；`check-style` |

## 可发展性（EV）

| 编号 | 需求 | 验收/机制 |
|------|------|-----------|
| EV-1 | Flash 分区表是**单一事实来源**，并为 A/B 升级预留槽位与元数据 | `flash-layout` 的 `MAP`（BSP/门禁/文档共同引用）；`check-flash-map` 双向核对；`check-image` 断言 LUT 4 字节地址相位 |
| EV-2 | 应用数据**单一属主**（文件系统）与文件语义；不得出现两个写同一片区域的属主 | `filesystem` 的 `BlockDevice` 边界；写队列由 `idle` 属主执行；`NullStore` 对未接线端口明确失败 |
| EV-3 | 外部设备通过**端口契约**接入：替换实现不动上层 | `ports` 的 `Bus`/`Clock`/`Store`/`LogSink`/`RawMedium`；主机替身在 `simulator`；`check-layering` 保证 ports 不含硬件依赖 |
| EV-4（方向） | 业务以独立 crate 参与**编译期组合**：接口不兼容在编译期失败；不引入运行期加载 | 当前由 `ports` + `check-layering` 保证边界；`sdk`/`Capsule`/产品组合根为后续实现（[架构与实现](../架构与实现.md)）。**注意：该行不是已实现需求，`trace` 目前不把它计入 30 条** |

## 可调试性（DB）

| 编号 | 需求 | 验收/机制 |
|------|------|-----------|
| DB-1 | 复位原因与故障现场必须**可解释**：CPU 状态可读、记录跨暖复位存活、"不可信的信息不打印" | `fault-decode`（SRSR/CFSR/HFSR/入栈帧/`CrashRecord` 解码）；BSP 的故障处理器（四个向量各有真实实现，`check-fault-handlers`）；启动横幅的 `reset :`/`上次故障:` 行 |
| DB-2 | 控制台输出必须**完整**且只有一个 `DATA` 写入者：队满按上下文分流、丢弃必须计数 | `board-support::console`（8 KiB 环形队列 + 中断排空；关中断时丢弃并计入 `txdrop`）；`cargo xtask bytecheck` 逐字节校验 |
| DB-3 | 日志必须结构化、可压缩落盘、默认不打终端：热路径只拷贝定长记录 | `log`（16 B 记录 + CRC-16、环形缓冲、三层字符串、LZ4/gzip 落盘路径） |
| DB-4 | 现场终端必须可诊断：命令表是唯一数据源，`help`/补全自动跟上 | `shell`（`COMMANDS` 表 + 行编辑 + ANSI）；`cargo xtask monitor`/`soak` 抓包判读 |
| DB-5 | 关键硬件状态必须**回读打印**（报事实，不报意图） | 启动报告的 `flash 4B`/`stack`/`dwt`/`id` 与 `diag` 的 `pit regs`/`region*` 回读；`check-image` 从链接产物断言 FCB/IVT/SP |

## 安全性（SF）

| 编号 | 需求 | 验收/机制 |
|------|------|-----------|
| SF-1 | 内存分区与缓存属性必须**生效且可回读**（Flash 只读可缓存、缓存里不得有 Flash 脏行） | `mpu-regions` 的区域表与 `check_state`；BSP 写寄存器后回读打印；`check-memory`/`check-image` 从产物断言 |
| SF-2 | 栈余量必须**实测**且不低于硬下限（≥30%） | `memory-layout` 的涂抹测量与 `MIN_STACK_HEADROOM_PERCENT`；启动横幅 `stack :` 行；启动横幅 `stack :` 实测与下限常量判读 |
| SF-3 | 链路不可信时**不得**继续驱动安全相关输出；安全状态不自动恢复 | `primitives::safety::SafetySupervisor`（失联优先的"与"判据；`Safe` 只能由重新上电/显式维护离开） |
| SF-4 | 喂狗必须由**任务健康门控**决定：必需健康位到齐才允许 | `primitives::safety::all_healthy`/`HealthBits`；固件里的 `REQUIRED_HEALTH_BITS` 聚合 |
| SF-5 | 连续多次复位必须进入安全状态（并留下可解释记录） | `SafetySupervisor::on_boot`/`clear_reset_streak`；`fault-decode` 的跨暖复位崩溃记录 |
| SF-6 | 危险写入必须 **fail-closed**：别名自检、范围/对齐/只读校验、损坏不得静默使用 | `nor-flash` 的 `check_erase`/`check_program` 与 4 字节寻址自检；`ports::StoreError::Rejected`；数据格式自带 CRC/版本门 |

## 可测试性（TS）

| 编号 | 需求 | 验收/机制 |
|------|------|-----------|
| TS-1 | 纯逻辑层必须能在**主机上完整重放**：不读寄存器、时间可注入、I/O 可替换 | `simulator`（`MockBus`/`ManualClock`/`MemMedium`/`CapturingLog`）；`check-layering` 的依赖闭包判据 |
| TS-2 | 掉电原子性必须**穷举注入**验证：对每个掉电点各跑一次 | `simulator/tests/power_cut_atomicity.rs`；`filesystem` 的掉电注入测试（含 GC 与格式化途中） |
| TS-3 | 主机侧行覆盖率必须 ≥90%（门禁） | `cargo xtask coverage`（工具链自带 `llvm-cov`，不新增依赖） |
| TS-4 | 上机实测必须有脚本与门禁：台架检查、烧录、抓包、逐字节校验 | `cargo xtask flash`/`monitor`/`bytecheck`；见 [构建与验证](../构建与验证.md) |
| TS-5 | 类型约束必须有**编译失败负例**（负例才是约束生效的证据） | `tests/compile-fail/`（`Cycles` 非零：`record(span, 0)` 必须编译不过）；`check-compile-fail` |

## 开放问题（不属于需求，故不参与追溯）

- **Q-A** 适用标准与目标安全等级（SIL? / PL?）——决定安全工程的全部工作量。
- **Q-B** 是否接受已鉴定的 Rust 工具链（Ferrocene）？若不接受，验证强度需上调。
- **Q-C** 接入侧的实际总线参数（波特率、帧率、超时）？平台预算只能给"默认串行 115200 / CAN 1 Mbps"作为起点。
- **Q-E** 安全状态（Safe State）的准确定义：撤除安全相关输出是否足够？
- **Q-F** 是否有独立人员可承担 IV&V？
- **Q-I** `WDG_CTR`（SGM706 看门狗禁用）由谁驱动？上电默认电平？固件能否在看门狗生效前拉高？若不由固件控制，看门狗触发后**只能断电恢复**。
- **Q-J** CAN **外部总线接收**未通的根因与验证条件（内部 loopback 已于 2026-10-19 实测 PASS，见 `board-support` 的 `GAP(P2)`）——需要第二块板/示波器，不靠改序列去猜。
- **Q-K** 升级方案（A/B 双槽 + 引导程序）的细节冻结：分区已预留（`GAP(P4)`），切换与回滚逻辑未实现。
