# Flash 布局与用途划分

> 分区表**唯一事实来源**是 [`crates/flash-layout`](../../crates/flash-layout/src/lib.rs)：
> BSP 引用它、`cargo xtask gate flash-map` 遍历它、下表的偏移由该门禁逐行核对。
> 本节只解释"为什么这样分"。

## 1. 寻址：整片 32 MiB 可用（不靠模式切换）

W25Q256 上电是 3 字节地址模式（上限 16 MiB）。项目采用**专用 4 字节地址操作码**
（读 `0xEC`、页编程 `0x34`、扇区擦除 `0x21`、块擦除 `0xDC`，地址相位 `0x20`），
**不做全局 EN4B 模式切换** —— 器件始终停在上电默认状态，序列没生效也不会把板子留在
非默认模式里（全局切换一旦序列失败可能直接变砖）。

两道锁：

1. 构建期：`cargo xtask gate image` 从 ELF 的 FCB LUT 断言三个序列的命令字节与地址相位；
2. 运行期：每次启动跑别名自检（读 `16 MiB + 0x1000`，不应再出现 IVT 魔数），
   启动横幅打印 `flash 4B : ... PASS`。

## 2. 分区表

全部 4 KiB 对齐；`SECTOR=4 KiB`、`BLOCK=64 KiB`、`XIP_WINDOW=32 MiB`。

| 分区 | 偏移 | 大小 | 用途 | 掉电策略 |
|---|---:|---:|---|---|
| `boot_header` | `0x000000` | 8 KiB | FCB + IVT + boot data | 运行期只读 |
| `bootloader` | `0x002000` | 248 KiB（256 KiB 区域含启动头） | 引导程序：选槽/校验/回滚（**P4 未实现**） | 整区（仅升级时） |
| `slot_run` | `0x040000` | 2 MiB | 实际运行槽 | 整槽（仅升级时） |
| `slot_backup` | `0x240000` | 2 MiB | 备份槽（新固件先写这里） | 整槽（仅升级时） |
| `boot_meta` | `0x440000` | 64 KiB | A/B 元数据：当前槽、试启计数、已确认 | 双份 + 序号 + CRC |
| `filesystem` | `0x450000` | 约 27.69 MiB | **全部应用数据** | 由文件系统保证 |

阶段 1（当前）：Bootloader 未实现，应用映像仍从偏移 0 起，临时占用 `bootloader` 预留区
（`0x2000..0x40000`）；`check-flash-map` 允许这一过渡状态，但拒绝映像进入 `slot_run`
及之后的分区。Bootloader 接入后应用迁到 `slot_run`。

两条必须独立成区的理由：

- `boot_meta` 不能放进文件系统 —— 引导程序要在**文件系统启动之前**知道启动哪个槽；
- `boot_header` 运行期绝对不能写 —— 写坏它只能靠 BOOT_MODE 引脚 + 串口下载器恢复。

## 3. 应用数据 = 文件（不切物理分区）

第一版曾按数据类型切 15 个分区，属过度设计：每多一个分区就多一套偏移/对齐/掉电策略/
磨损预算，而这些差异本质上是**文件语义**差异。最终收敛为 6 个功能分区，应用数据全部
由文件系统管理：

| 路径 | 语义 |
|---|---|
| `/config/config.bin` | 应用参数（整体覆盖） |
| `/config/calib.bin` | 现场标定（长期有效） |
| `/log/reset.log` | 复位台账（只追加） |
| `/log/blackbox.log` | 事件黑匣子（只追加文本） |
| `/log/spool.log` | 遥测/事件缓冲（只追加） |
| `/factory/factory.bin` | 出厂信息（写一次） |

路径是 Linux 风格**绝对路径**，但没有独立目录 inode：目录由路径前缀隐含，`list_dir`
从现有文件路径合成直接子项；不支持 `mkdir`/`rename`/硬链接/权限。文件数是上限 16 的小集合，
换来零新增介质格式、零新增 RAM、掉电语义与记录一致。

**单一属主**：文件系统是持久化数据的唯一写入者；除文件系统外任何分区与文件系统区间相交
都会被 `check-flash-map` 拒绝（历史上出现过"两张原始偏移表与文件系统块 0 重叠"的事故）。
