# 构建与验证（仓库怎么用）

> 唯一验收口径：`cargo xtask verify`。**优先用 cargo/xtask**；`make` 只是薄包装，
> 台架脚本（烧录/抓包/逐字节校验）仍由 `scripts/` 承担。

## 1. 环境

| 项 | 说明 |
|---|---|
| Rust | **最新 stable**（根 `rust-toolchain.toml`；不锁定具体补丁版本） |
| 目标 | `thumbv7em-none-eabihf`（默认 target，直接 `cargo build --release` 就是固件） |
| 主机测试 | 必须显式 `--target x86_64-unknown-linux-gnu` |
| 台架 | pyocd + pyserial 装在 `.venv/`（`make setup` 或 `bash scripts/setup-bench.sh`） |
| 探针/串口 | SWD `/dev/pudu-debugger-swd`，串口 `/dev/pudu-debugger-16p-uart`（可用 `BASE_SERIAL`/`PYOCD` 覆盖） |

## 2. 日常命令

```bash
cargo xtask verify        # 全量：静态门禁 + fmt/clippy + 主机测试 + 目标构建 + 产物断言
cargo xtask gates         # 18 项静态门禁逐条 PASS/FAIL（不因第一个失败而中断）
cargo xtask context       # 机器可读上下文（crate/门禁/缺口/预算/最近测试结果）
cargo xtask test-host     # 主机测试
cargo xtask lint-host     # 主机 clippy
cargo xtask lint-target   # 固件目标 clippy
cargo xtask coverage      # 主机行覆盖率（阈值 90%）
cargo build --release     # 构建固件 ELF
```

单项门禁（都在 `verify` 里，排查时单独跑）：

```bash
cargo xtask check-layering      # 纯逻辑 crate 依赖闭包不含硬件 crate
cargo xtask check-capsules      # 依赖 sdk 的插件不得直接依赖 BSP/固件
cargo xtask check-interrupt-priorities  # 中断任务优先级与预算表一致
cargo xtask check-unsafe        # unsafe 块与 SAFETY 配平、不超预算
cargo xtask check-critical      # 关中断只能走测量入口
cargo xtask check-docs          # 文档数字/可达性/命令存在性
cargo xtask check-memory        # .text 在 ITCM 且不超预算、栈在 DTCM
cargo xtask check-image         # FCB/IVT/LUT 4 字节相位/初始 SP
cargo xtask check-flash-map     # 分区表自洽 + 文档表格一致
cargo xtask check-size          # 映像 < 1 MiB
cargo xtask check-code-placement# .xip 白名单
cargo xtask check-fault-handlers# 四个故障向量各有真实实现
cargo xtask check-compile-fail  # 编译失败负例确实失败
cargo xtask check-style         # 无 todo/unimplemented、模块文档、lint 未放宽
cargo xtask check-lint-headers  # 每个 crate 的标准 lint 头
cargo xtask check-api-usage     # 无调用者的公开项（不失败，但可见）
cargo xtask check-gaps          # 清点 GAP(Px)（不失败，但可见）
cargo xtask trace               # 需求追溯矩阵（生成 docs/01-需求/需求追溯矩阵.md）
```

## 3. 真机（烧录/抓包/自测）

```bash
bash scripts/flash.sh -e chip   # 全片擦除 + 烧录（改分区/FS 格式后必须擦全片）
bash scripts/flash.sh           # 普通烧录（不带 -e chip）
bash scripts/read_console.py --seconds 5   # 只看串口
bash scripts/monitor.sh         # 抓串口并校验时基漂移（±2%）
bash scripts/check-bench.sh     # 台架就绪检查（探针/SWD/pyocd；串口别名缺失只警告）
```

上机验证入口（Makefile 薄包装）：

| 目的 | 命令 |
|---|---|
| 控制台逐字节校验（改时钟/中断/控制台后必跑） | `make bytecheck` |
| 目标端自检 5 项（复位 → selftest） | `make test-target` |
| 台架就绪检查 | `make check-bench` |
| 时基漂移检查 | `make monitor` |
| 全片擦除烧录 | `bash scripts/flash.sh -e chip` |
| 复位 | `make reset` |

- `make bytecheck` 的期望文本来自仓库根 `banner.txt`（构建期注入横幅）。
- 串口被占用（`EBUSY`）时先确认没有别的 `screen`/抓包进程持有设备；不要直接杀用户进程。

## 5. 版本号

- `VERSION` 是唯一真源（`crates/firmware/build.rs` 构建期注入并校验格式），格式 `0.1.2.0`；
- **改固件行为就递增**；只改文档/工具不递增；
- 发布检查：`cargo xtask verify` → `cargo xtask coverage` → 真机 `make bytecheck` +
  `make test-target`；本次重构把原 `bench` 性能基线门禁移除了（见下）。

## 6. 本次移除：bench 目录与性能基线门禁

`bench/` 原先只存一份手工录制的启动测量基线（Flash 读吞吐、FS 挂载、SDRAM 自检、
栈余量、`rt`、`txdrop`），由原 bench 子命令对比。它的判据与真机台架强耦合、
易受缓存/温度影响，维护成本大于收益，**已删除**（命令、Makefile 目标、基线文件一起移除）。
真机事实仍由启动横幅回读 + `bytecheck`/`test-target`/`monitor` 提供。

## 7. 排障

| 现象 | 处理 |
|---|---|
| 串口 `EBUSY` | 查持有者（`screen`/抓包进程），让用户释放；不要擅杀 |
| 编译通过但板子不启动 | 先 `cargo xtask check-image`；再确认烧录偏移 0 和 FCB |
| 改了分区/FS 格式后异常 | 必须 `bash scripts/flash.sh -e chip` 全片擦除 |
| `cargo xtask verify` 红 | 先跑 `cargo xtask gates` 看是哪条；文档数字不一致按提示改文档 |
| pyocd 找不到 | `make setup`；或设 `PYOCD=/path/to/pyocd` |
