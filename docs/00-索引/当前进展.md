## 1.5 架构演进：静态 capsule 化内核

**方向已冻结；S1（组合根外提）已落地，S2/S3 尚未实现。** 目标形态：

```text
core kernel（board-support/firmware）→ 基础 capsule（纯逻辑层）→ 业务 capsule（仓库外 crate）
```

- 全部编译期静态组合，运行期零加载、零热替换；
- 业务 capsule 禁止 unsafe / 寄存器 / RTIC 任务，只依赖 capsule SDK 或端口；
- 中断、调度、实时预算归 core kernel；
- `forbid(unsafe_code)` 是代码纪律，**不是安全隔离**；可信插件模型不等于不可信第三方隔离。

当前状态（S1，`0.1.0.0`）：

- **已实现**：`sdk` 门面（`Capsule<C>` / `CapsuleSet` / `Product` / `prelude`）；
  产品组合根外提为纯逻辑 crate `product`（只依赖 `sdk`），`firmware` 经
  `src/platform.rs` 实现 `product::Platform` 注入六个内置服务；旧 `composition.rs` 已删除；
  插件门禁 `check-capsules`（**只扫仓库内 `crates/`**）。
- **未实现**：S2 上下文能力对象化（`sdk::CapsuleContext` / 能力句柄）、
  S3 基础 capsule 外提与仓库外插件门禁、事件分发 `on_event`、capsule 级预算/健康。
  仓库外业务 capsule 目前只能写无能力的 `impl<C> Capsule<C>`。
- 现有业务接入仍按 [`业务接入指南`](../02-架构/业务接入指南.md) 的方式工作。

完整决策与边界见 [ADR-0008](../adr/0008-静态capsule化内核.md)、
[ADR-0010](../adr/0010-产品组合根外提.md)、
[`微内核与capsule架构`](../02-架构/微内核与capsule架构.md) 与
[`产品组合根外提设计`](../02-架构/产品组合根外提设计.md)。

## 1.6 启动时序与终端响应

- banner 在 `board::init` 里、SDRAM/文件系统长活之前用阻塞写输出；
  真机实测 banner 首行约 **0.85 s**。
- 归档索引不再在启动路径加载：`archive_init` 曾在提示符之后执行，`fs` 名字索引
  不完整时会退化为全盘下探，导致“提示符已出、输入却卡约 3 s”。现在启动不加载索引；
  `log stats` / `log verify` / `log restore` / 首次归档时才由 `archive_ensure`
  承担重建成本。实测提示符出现后 **50 ms** 内即可回显输入。
- SDRAM 自检分级：**上电 / 看门狗 / lockup 复位**跑 32 MiB 全片（约 3.3 s）；
  **调试器软复位 / 终端 reboot** 只跑 1 MiB 快速自检（约 143 ms）+ 50 ms 保持检查。
  全片自检仍可随时用终端 `memtest` 手动执行。
- 当前真机（暖复位）：banner 0.85 s、终端提示符约 **1 s**、输入回显 50 ms；
  文件系统为 **442 数据块 + 1 索引块**；无索引时全盘扫描约 **18 ms**，
  `fs checkpoint` 后重启走持久化索引。
- `cargo xtask bench` 的 SDRAM 项记录的是暖复位快速自检（基线 143 ms），
  不再把 3.3 s 全片测试算进每次启动；全片路径由 `memtest` 覆盖。
- **GC 稀疏合并**：`gc()` 在死字节回收之后，还会挑选“使用率 < 1/4 且仍有活记录”的块，
  搬走活记录再擦除。它解决的是“死数据为 0 但一块只有一条小记录”的布局；挂载时间不再只靠全片擦除。
- **日志收敛**：早期二进制日志资产已删除；文本日志增加级别过滤
  （默认 Info）、`log on/off/level/dump/prev`、`.uninit` 崩溃尾部镜像；
  落盘改为 512 B 攒批且单条 FS 请求上限 1 KiB，`log clear` 改为删除文件 + GC。

## 4. 验证状态

最近一次通过：

```text
cargo xtask verify      全绿（450 个主机测试，覆盖率 90.41%）
make test-target        5/5 PASS（0.1.0.0）
make bytecheck          通过（0.1.0.0）
cargo xtask bench --record  rt=ok / txdrop=0 / 栈余量 89%（0.1.0.0，基线已重录）
make release-check      exit 0
```

关键真机修复：

- `run_selftest` 从 XIP 改回 ITCM；
- 根因：selftest 调用裸 Flash 擦写后返回 XIP，偶发 IACCVIOL/HardFault；
- 这是之前 `test-target` 长期不稳定的根因。

## 7. 下一阶段规划

### P0：先把当前稳定基线守住

1. 保持 `verify` / `test-target` / `bytecheck` / `bench` / `release-check` 全绿；
2. 新增功能必须继续补主机测试，避免覆盖率跌破 90%；
3. 文档常量持续由 `check-docs` 机械核对。

### P1：日志与归档（已完成）

1. ✅ 归档去复制：generation 文件 + 64 B 持久索引，轮转只写新窗口、删最旧窗口；
2. ✅ 归档元数据：generation / 压缩字节 / 源字节 / 文件 CRC-32；
3. ✅ `log restore [n]`：按 generation 从旧到新恢复最近 n 个窗口，输出合并 CRC-32；
4. ✅ `log verify`：逐窗口 gzip + 索引 CRC 校验，并给出合并 CRC-32 汇总。

### P2：诊断与可观测性（已完成）

1. ✅ 接线 RX 丢弃（心跳 `rxdrop=`）、CAN 故障收敛/邮箱标志、flash 阶段号；
2. ✅ `fs scan`：在属主上下文做全盘存活统计，不在关中断里扫描；
3. ✅ 启动日志记录 reset streak、flash 阶段与上次故障摘要；
4. ✅ 连续复位台账（`bump_reset_streak`）接线，稳定运行 10 s 后清零。

### P4：验证与交付

1. 长稳 soak、掉电/复位矩阵；
2. 保持本地 `master`、tag、证据账本同步；
3. 在明确授权前不 push 到 `origin`。
