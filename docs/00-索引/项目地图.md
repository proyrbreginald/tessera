# 项目地图（一页纸）

> **Tessera**：MCU 实时底座。core kernel + 基础 capsule，提供启动链、外设驱动、存储、
> 日志、实时仪表、故障解码、终端与门禁；**不含业务语义**（业务是仓库外的 crate）。
> 项目当前 **20 个成员 crate**（其中 18 个纯逻辑，可主机测试）+ `xtask`。

## 1. 规模与门禁

| 项 | 值 |
|---|---|
| 工作区成员 crate | **20** |
| 纯逻辑 crate（门禁口径） | **18** |
| 硬件实现 crate | 2（`board-support`、`firmware`） |
| 静态门禁子命令 | **18** |
| 未实现缺口 | 3（P2/P4/P5，见 [安全与约束](../安全与约束.md)） |
| 唯一验收入口 | `cargo xtask verify` |

会漂移的测量值（主机测试数、覆盖率、映像字节数）不要写在这里：
用 `cargo xtask context` 一次取全。

## 2. 分层（编译期事实）

```text
业务 crate（仓库外，编译期静态组合，可无能力）
        │  依赖 sdk / ports
纯逻辑层（18 个 crate，forbid(unsafe_code)，可主机测试）
        │  依赖 ports / sdk，不碰寄存器
board-support（唯一允许碰寄存器的 BSP）
        │
firmware（RTIC 应用：只做接线、任务划分、健康位聚合）
```

- 依赖闭包里出现 `imxrt-*`/`cortex-m*`/`rtic` 的实现层代码即失败：`cargo xtask check-layering`。
- 依赖 `sdk` 的插件 crate 不得直接依赖 BSP/固件：`cargo xtask check-capsules`。
- 依赖表见 [分层与依赖规则](../02-架构/分层与依赖规则.md)。

## 3. 启动与存储

```text
Boot ROM → FCB(0x0) → IVT(0x1000) → 应用（阶段 1：从偏移 0 起，单槽）
```

- 外部 Flash：W25Q256JVEQ 32 MiB（QSPI XIP `0x6000_0000`，专用 4 字节操作码）；
- 分区：启动头 8 KiB / 引导程序 248 KiB / 槽 A 2 MiB / 槽 B 2 MiB / A/B 元数据 64 KiB / 文件系统约 27.69 MiB；
- 应用数据全部进文件系统（`/config` `/log` `/factory`）；分区表唯一来源是 `crates/flash-layout`。
- 详细数字见 [Flash 布局与用途划分](../02-架构/Flash布局与用途划分.md)。

## 4. 运行时（当前）

- **RTIC v2**，静态任务；仅两个硬件中断：`LPUART1`（控制台 RX，优先级 1）、`PIT`（时基，优先级 1）；
- `idle` 是协作式循环：输入 → 维护（FS/日志/轮转）→ 健康 → 1 Hz 内务 → `wfi`；
- 不用 `async`、不用通用堆、不用 `defmt`；`alloc` 只允许固定块静态池（终端/诊断/压缩器）。

Tock 是**后续固定运行时**（不再选型/不会替换）：源码 vendored 在顶层 `tock/`
（上游裁剪 + 本地板级 crate）；当前生产固件仍为 RTIC，迁移按
[Tock 运行时](../Tock运行时.md) 的前置条件推进。

## 6. 怎么验证一件事

| 想验证 | 命令 |
|---|---|
| 全量门禁 + lint + 主机测试 + 目标构建 + 产物断言 | `cargo xtask verify` |
| 静态门禁逐条状态 | `cargo xtask gates` |
| 项目上下文（JSON） | `cargo xtask context` |
| 真机烧录/串口/自测 | 见 [构建与验证](../构建与验证.md) |
| Tock 运行时（迁移中） | `cargo xtask tock-verify` |
