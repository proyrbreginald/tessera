## 0. 一分钟定位

```text
外部世界（由接入方的**业务 capsule** crate 定义，位于本仓库之外）
        │  通过 capsule SDK / ports 的端口契约（Bus / Clock / Store / LogSink / RawMedium）
        ▼
本底座 = core kernel + 基础 capsule
        ├─ core kernel：启动链 / 外设驱动 / 中断 / MPU / 故障处理 / 调度与实时预算
        ├─ 基础 capsule：终端 / 存储 / 日志 / 协议 / 诊断 / 门禁
        └─ 上机实测：同一份门禁本地与 CI 一致；业务在主机上完整重放
```

本底座是**与应用无关的基础设施**：它提供"让上层业务写起来简单、且能脱离目标机测试"所需的
全部接缝（端口、替身、门禁、诊断），但**不含任何业务语义**。

**架构方向是静态 capsule 化内核**：业务 capsule 是独立 crate，编译期与底座一起链接；
不做运行期热替换，也不把 safe capsule 宣称为安全隔离。完整边界见
[`微内核与capsule架构`](../02-架构/微内核与capsule架构.md) 与
[ADR-0008](../adr/0008-静态capsule化内核.md)。
核心工程主张：**未知要被隔离成一个类型，而不是散落成猜测** —— 未接线/未确认的能力
一律以明确错误变体暴露（`NotImplemented` / `Rejected`），并由
`GAP(Px)` + `check-gaps` 清点。

## 3. 存储地图

### 3.1 外部 NOR（`W25Q256JVEQ`，32 MiB，4 KiB 扇区 / 64 KiB 块）

唯一事实来源：[`crates/flash-layout/src/lib.rs`](../../crates/flash-layout/src/lib.rs)
（BSP、`check-flash-map`、文档三方引用同一份数据）。以下为 `cargo xtask check-flash-map` 的实际输出：

| 偏移 | 大小 | 用途 | 掉电策略 | 名称 |
|---:|---:|---|---|---|
| `0x000000` | 8 KiB | 启动头（FCB + IVT + boot data） | **运行期只读** | `boot_header` |
| `0x002000` | 248 KiB（256 KiB 区域含启动头） | 引导程序：复制、校验、回退（未实现） | 整区替换（仅升级时） | `bootloader` |
| `0x040000` | 2.00 MiB | 运行槽 | 整区替换（仅升级时） | `slot_run` |
| `0x240000` | 2.00 MiB | 备份槽（新固件写入） | 整区替换（仅升级时） | `slot_backup` |
| `0x440000` | 64 KiB | run/backup 元数据：状态、复制进度、试启 | 双份 + 序号 + CRC | `boot_meta` |
| `0x450000` | 约 27.69 MiB | **全部应用数据**（文件系统） | 由文件系统保证 | `filesystem` |

合计 `0x2000000` = 32 MiB 全部划完；`SECTOR = 4 KiB`、`BLOCK = 64 KiB`、`XIP_WINDOW = FLASH_SIZE = 32 MiB`。

- **整片可用靠专用 4 字节操作码**（读 `0xEC`），不用 `EN4B(0xB7)` 模式切换——后者会把器件留在非上电默认状态。
- 两道保护：构建期 `check-image` 断言 LUT 相位；运行期每次启动做 16 MiB 别名自检（读 `16 MiB + 0x1000` **必须不是** IVT 魔数）。
- 应用数据以**文件**住在 `filesystem`：`config.bin`（整体覆盖）、`calib.bin`（标定）、`reset.log`/`blackbox.log`/`spool.log`（只追加环形）、`factory.bin`。文件名**不带前导斜杠**（扁平命名空间）。
- **FS 块头磁盘格式**（唯一事实来源：[`crates/filesystem/src/layout.rs`](../../crates/filesystem/src/layout.rs)）：块头 16 B = 魔数 `"ELFS"`(4) + 序号(4) + 状态(1) + **格式版本(1)** + **擦除计数 `u32`(4)** + CRC-16(2)；记录头 16 B。擦除计数 2026-10-12 由 `u16` 加宽为 `u32`（偏移 12 → 10）：器件寿命是 10 万次/块，`u16::MAX = 65535` 只到 **65.5%**，到顶后计数静默饱和。
- ⚠️ **FS 块头格式变更必须全片擦除重刷**：`bash scripts/flash.sh -e chip`。版本字节只保证旧版式被**判为无效**，不保证它被清除 —— 旧头一旦判无效，那一块的**磨损计数就从 0 重新计起**，磨损统计会失真。

### 3.2 片内 FlexRAM（256 KB = 8 bank × 32 KB）

> 布局常量的唯一事实来源是 [`crates/memory-layout`](../../crates/memory-layout/src/lib.rs)；
> 下表是**实测占用**，不是那些常量本身。**下表为 2026-10-22 快照**：会变的测量值以
> `cargo xtask check-memory` 与 `arm-none-eabi-size -A` 的实时输出为准。

| 区域 | 地址 | 大小 | 放什么（本次实测） | 余量 |
|---|---|---|---|---|
| ITCM | `0x0000_0000` | 64 KiB | 全部 `.text` 54,868 B | 2,476 B |
| DTCM | `0x2000_0000` | 64 KiB | `.stack` 48 KiB（`0x2000_0000`..`0x2000_C000`）+ `.vector_table` 632 B @ `0x2000_C000` | ~15 KiB |
| OCRAM | `0x2020_0000` | 128 KiB | `.rodata` 28,188 + `.data` 15,968 + `.bss` 8,944 + `.uninit` 72 = 53,172 B；顶 64 KiB 是非缓存 DMA 池 @`0x20210000` | ~12.1 KiB |

- **Boot ROM 需要一个 OCRAM bank**，所以 OCRAM 从 `0x2020_0000` 而不是 `0x2000_0000` 起。
- `__heap_size = 0`：无通用堆。集合用 `heapless`，容量是编译期常量；`alloc` 走 SDRAM 两段固定块静态池（1 KiB×2048 + 128 KiB×32，见 `board-support::alloc_pool`）。
- 分工原则（[`资源利用与优化评审`](../02-架构/资源利用与优化评审.md) §3.2）：ITCM 放代码与 ISR 热路径、DTCM 放栈/向量表、OCRAM 放常驻工作区、SDRAM 放大缓冲。

### 3.3 外部 SDRAM

| 项 | 值 |
|---|---|
| 器件 / 容量 / 基址 | `W9825G6KH-6I`（TSSOP-54，`U20`）/ 32 MB / `0x8000_0000`（SEMC CS0） |
| SEMC 时钟 | **62.5 MHz**（PLL_SYS 528 MHz → PFD2 500.2 MHz → PODF /8），与既有 C 固件 `clock_config.c` 一致 |
| 状态 | **已初始化 + 全片自检通过**：`pattern_test` 覆盖 32768 KiB、0 错误；写入后 250 ms 读回 4/4 保持（专抓"刷新没开"）。暖复位走 1 MiB 快速自检（143 ms） |
| 用途 | 自检 + 两段固定块 **alloc 池**（终端/诊断与 gzip 压缩器状态） |
| 三处刻意偏离既有 C 固件 | ①`MCR[DQSMD]=0`（本板无 `SEMC_DQS` 网络）②SEMC 寄存器用**真实偏移**而非 RAL 字段名（RAL 0.6.2 的块偏移整体前移 4 字节，会让每条 IP 命令"立刻完成"却未执行）③焊盘电气沿用 Boot ROM DCD 的 `0xE1` |

🟡 容量在资料内自相矛盾（原理图 p3 写 32MB、p13 注记按 8M×16×4 推算 64 MB）；固件按 32 MB 处理并自检通过。

## 4. 代码地图与门禁

### 4.1 分层（编译期事实）

```text
业务 capsule（仓库外，独立 crate）
        │ 只依赖 capsule SDK / ports；禁止 unsafe / 寄存器 / RTIC 任务
        ▼
基础 capsule / kernel-support（纯逻辑层，18 个 crate）
primitives ──▶ wire-format ──▶ ports ──▶ filesystem / simulator / firmware …
       │           │              ▲
       ├──▶ sdram-timing / shell / flash-layout / mpu-regions / memory-layout /
       │    realtime / fault-decode / block-pool / log / gzip / nor-flash
       │
       └──▶ simulator（主机替身，仅测试/自检）

core kernel（唯一允许 unsafe / 寄存器）
board-support（唯一碰 imxrt-* 的库）─▶ firmware（平台注入）
product（产品组合根，只依赖 sdk）─▶ firmware 经 `Platform` 注入服务
```

（完整依赖表见 [`分层与依赖规则`](../02-架构/分层与依赖规则.md)；`check-layering` 从
Cargo 依赖闭包逐 crate 强制。）

`check-layering` 强制 **18 个纯逻辑 crate**
（core/proto/ports/sim/sdk/product/semc/shell/flashmap/fs/mpu/memory/rt/fault/pool/log/gzip/flash）
的依赖闭包里**没有** `imxrt-hal`/`imxrt-ral`/`imxrt-rt`/`imxrt-boot-gen`/`cortex-m`/`cortex-m-rt`/`rtic`
（连 `dev-dependencies` 也查）。名单的唯一来源是 `xtask` 的 `PURE_CRATES`。

**接入方业务不在本仓库**：业务 crate 通过 capsule SDK / `ports` 的端口契约接入，
用 `simulator` 在主机上重放（见 [`业务接入指南`](../02-架构/业务接入指南.md)）。
capsule 化是**已冻结的方向**：`sdk` 门面、`Capsule` trait、`Product` 模板与产品组合根（`product`）已落地（S1）；
`check-capsules` 只覆盖仓库内。S2 上下文能力对象化与 S3 基础 capsule 外提**尚未实现**，
仓库外业务 capsule 目前只能写无能力的 `impl<C> Capsule<C>`。

### 4.2 门禁清单

| 门禁 | 检查什么 | 现状 |
|---|---|---|
| `check-layering` | 18 个纯逻辑 crate 无硬件依赖 | ✅ |

## 6. 缺口与里程碑

### 6.1 `cargo xtask check-gaps` 现状（3 项，全部是平台能力）

|---|---|---|---|

| **P4** | run/backup 引导与复制恢复未实现（分区已预留、门禁已就位） | `crates/flash-layout/src/lib.rs` | 复制进度、校验、回退逻辑待实现 |

### 6.2 里程碑全景

| 里程碑 | 内容 | 状态 |
|---|---|---|
| P1 | 平台可用：启动链、控制台、64 位时基、SDRAM、MPU/cache、栈测量、文件系统、终端、故障解码 | ✅ 2026-10-13 真机验证关闭 |

| P3 | 持久化与日志 | ✅ 文本日志全链路已通；二进制旧资产已删除 |
| P4 | 升级：run/backup + 引导程序 + 复制恢复 | 未开始：`GAP(P4)` |

## 7. 怎么验证一件事

| 想验证的东西 | 套路 | 具体命令 / 判据 |
|---|---|---|
| **纯逻辑**（状态机、编解码、时序、存储策略） | 主机测试；需要"能推进时间/能注入掉电"就用 `simulator` 的 `ManualClock` / `MockBus` / `MemMedium` | `cargo test --target x86_64-unknown-linux-gnu -p primitives`（换 crate 名）；掉电原子性用"对每个掉电字节位置各跑一次"的穷举 |
| **硬件寄存器 / 时序 / 布局** | ①构建期断言 ②产物级 ELF 断言 ③启动报告 / `diag` **回读打印** | `cargo xtask check-image`、`check-flash-map`、`check-size`、`check-memory`；串口上核启动报告的 `flash 4B`/`stack`/`dwt`/`id`，原始寄存器用 `diag` |
| **真机行为**（电气、真实时序、掉电） | 台架门禁 → 烧录 → 抓串口 | `make check-bench` → `make flash`（改过布局必须先 `bash scripts/flash.sh -e chip` 全片擦除）→ `make monitor`（自动发 `beat on`，比对设备 `uptime` 与主机时间，容差 ±2%） |
| **控制台输出完整性**（丢字节/错位） | **逐字节**比对抓包与期望文本（肉眼不可靠：丢字节常只出现在长输出的后半段） | `make bytecheck`（复位 → 抓包 → **剥离 ANSI 后用增量解码器**逐条比对；失败时打印缺失的那一条） |
| **实时性有没有达标**（关中断是否超预算；⚠️ **启动期与运行期分开判**：`boot-init` 预算 50 ms；2026-10-19 把 SDRAM 自检搬到 `idle` 后实测 ≈8 ms（此前 ≈3.25 s）） | ①运行时**实测**：DWT 周期计数器包住每一处临界区与 ISR；②台账按需 dump：终端 `rt` 命令；③**心跳**（`beat on` 开启；默认不打印）带 `rt=ok\|VIOLATION\|none`（三态；`none` = 一次都没测过，不许当成合格）；④静态纪律：`check-critical` 拒绝绕过测量入口的临界区 | 关中断预算见 `realtime::BUDGET_IRQ_OFF_MICROS`（80 µs），与 115200 8N1 串行总线字节间隔 86.8 µs 的关系由 `const_assert!` 钉在编译期 |
| **性能有没有退化** | 真机基准与基线比对（判据是**百分比与绝对量同时超限**） | `cargo xtask bench`（基线 [`bench/baseline.json`](../../bench/baseline.json)，`--record` 重采；`--from-file <抓包>` 可**离线**验证解析逻辑本身） |
| **主机侧测到什么程度** | 覆盖率门禁（阈值 90%） | `cargo xtask coverage`（`-C instrument-coverage` + 工具链自带 `llvm-cov`，**不新增依赖**） |
| **文档数字是否与代码一致** | 机器判据（不是靠人复查） | `cargo xtask check-docs`（成员/纯逻辑 crate 数、静态门禁条数、unsafe 预算、缺口数 + 可达性 + 命令存在性） |

**未知的处置**：新发现的缺口 → 留 `GAP(Px)` + 返回明确错误变体，然后登记到
[`模块分解.md`](../02-架构/模块分解.md) 的未实现清单（必要时同步 [`需求规格.md`](../01-需求/需求规格.md) 的开放问题）。
**不要**用 `todo!()`，也**不要**填一个"看起来合理"的默认值。

## 8. 取数方法（便于复核）

```bash
export PATH="$HOME/.cargo/bin:$PATH"
# 全量口径（静态门禁 + fmt/clippy + 主机测试 + 目标构建 + 产物断言）
cargo xtask verify 2>&1 | tail -30

# 单项门禁（汇总表：cargo xtask gates）
cargo xtask check-{layering,lint-headers,unsafe,gaps,fault-handlers,critical,api-usage,style,docs,memory,code-placement,image,size,flash-map,compile-fail}
cargo xtask trace

# 规模：crate 名单与主机测试总数
cargo xtask pure-crates
cargo xtask test-host 2>&1 | grep -E '^test result: ok\. [0-9]+ passed' \
  | awk '{s+=$4} END {print "TOTAL PASSED="s}'

# 段占用 / 关键地址
arm-none-eabi-size -A target/thumbv7em-none-eabihf/release/firmware
arm-none-eabi-nm target/thumbv7em-none-eabihf/release/firmware \
  | grep -E '__image_size|__ivt|__boot_data|Reset|__pre_init| main$|__sstack'

# 覆盖率（主机侧，阈值 90%）
cargo xtask coverage
```

> 提醒：`xtask` 不是工作区成员，必须用 `cargo xtask ...` 别名（见 [`.cargo/config.toml`](../../.cargo/config.toml)）；
> 本机 `cargo` 在 `~/.cargo/bin`，非登录 shell 里可能需要先 `export PATH="$HOME/.cargo/bin:$PATH"`。
