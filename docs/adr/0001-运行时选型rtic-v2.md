# ADR-0001：运行时选型 RTIC v2

## 状态

已采纳（决策）

## 决策

运行时选 **RTIC v2**：编译期静态优先级、编译期无锁资源借用、零动态分配。

## 理由

硬实时的外部总线收发需要**可证的**抖动上界，而不是"实测还行"。

| 候选 | 判定 | 理由 |
|------|------|------|
| 裸机超级循环 | ❌ | 多个外部设备的收发互相阻塞，时序不可证 |
| **RTIC v2** | ✅ | 静态优先级 + 编译期检查无死锁/数据竞争 + 零动态分配 |
| Embassy（async） | ❌ | 单执行器无抢占：实时性从"结构保证"退化为每个任务的"让出纪律" |
| 自研 RTOS | ❌ | 需自证调度器正确性 —— 在认证语境下是最坏选择 |

> 2026-10-27 追加：另做过一次 **Tock 2.3.0 替换 RTIC 的最小真机验证**（启动/中断/UART
> 回显通过，但未迁移 caps/进程/BSP）。结论与前置条件见
> [`Tock替换RTIC验证`](../02-架构/Tock替换RTIC验证.md)；本 ADR 仍是生产运行时决策。

## 后果

- **正面**：实时性成为结构性事实；`critical-section` 的细粒度借用取代全局关中断，
  直接消除"高优先级 ISR 关中断过久导致串行总线丢字节"这一最致命风险。
- **代价**：RTIC 本身**没有功能安全证书**，因此它成为"需被论证的可信基础" ——
  必须用其**设计**（静态优先级、编译期无锁）做论证，并配以运行时证据
  （关中断时长监控、任务优先级与 `budget::prio` 的编译期一致性断言）。见 [安全计划](../05-安全/安全计划.md)。
- 与 [ADR-0003](0003-不使用alloc与async.md)（不用 async）互为支撑。
