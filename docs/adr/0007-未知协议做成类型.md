# ADR-0007：未知协议做成"没有默认值的类型"

## 状态

已采纳（决策）

## 决策

未接线 / 未确认的外部接口与协议**不做任何默认填充**：能返回错误的地方就返回明确的
错误变体（`NotImplemented` / `Rejected`）；物理层与协议参数集中在
`board-support/src/config.rs` 一张表里、**逐条标注确认状态**（✅ 有依据 / 🟡 待确认，
🟡 项不得当事实使用）；未实现点用 `GAP(Px)` 标记并由 `cargo xtask check-gaps` 清点。

## 理由

面对未知有两条路：

| 做法 | 后果 |
|------|------|
| 填一组"看起来合理"的常量 | 所有人（包括未来的自己）以为它是对的；错误扩散到测试与文档 |
| 把未知收敛成一个必须有人回答的接口 | 强迫回答"这些值从哪来"；错误限制在一处 |

本项目选后者。收益是"固件会不会使用未经确认的字节与电气参数"这个问题在**代码里**
就有答案 —— 它不会，并且有测试固定这一点（`ports` 的
`unimplemented_regions_are_visible_not_panicking`）。

相比 `todo!()`：未实现是**可观测的运行时事实**（`NotImplemented` / `NotConfigured` /
`Rejected` 错误变体），而不是一次 panic —— 后者在 ISR 里可能表现为静默挂死。

## 后果

- **正面**：外部接口确认后改动面极小（实现一个 trait + 换组合根一行；物理层确认后改
  `config.rs` 一张表）。
- **代价**：在外部接口确认/接线之前，相关操作**不可用**（这是刻意的，而不是"部分可用"
  ——后者更危险，因为会让人以为整条链路通了）。
- 相关：`cargo xtask check-gaps` 会列出全部未实现项及其里程碑归属。
