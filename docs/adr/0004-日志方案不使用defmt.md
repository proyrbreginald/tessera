# ADR-0004：日志方案 —— 不用 defmt

## 状态

已采纳（决策）

## 决策

自研分级日志抽象（`ports::log::LogSink`），现场通道是 **UART 文本**；
`defmt` 仅作为将来有网络时的**可选开发通道**，不进默认构建路径。

分级：`Error`/`Warn` 常开，`Info` 默认关，`Debug` 仅开发构建。
ISR **绝不**直接写日志，只累加原子计数。

## 理由

1. **现场故障恰恰发生在没有调试器的时候**，而 defmt 需要 RTT/半主机才能读出日志。
   "故障时恰好没有日志"是最糟的观测方案失效。
2. defmt 会把一整条依赖链带进固件，**扩大需要论证的工具面** —— 与安全目标相反。
3. `imxrt-hal` 0.6 的隐式 `defmt` feature 会强拉 `defmt 1.0`；本机离线依赖集中
   没有 defmt，开了就编不过（可构建性也是硬约束）。

## 后果

- **正面**：现场可读、可被台架脚本解析、可人眼直读；依赖面最小。
- **代价**：文本格式占用串口带宽（115200 下 60 字节约 5 ms），因此只能在空闲任务输出；
  高速结构化日志要等 defmt 作为可选通道接入。
- 输出格式固定为 `级别 秒.微秒 来源: 正文`，并有单测固定
  （`Record::Display` 的字段顺序是**可被脚本依赖的契约**）。
