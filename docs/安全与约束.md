# 安全与约束

> 平台的安全立场与硬约束。安全等级/标准（SIL/PL）尚未确定；本文不假设认证等级。

## 1. unsafe 纪律

- 预算文件：根目录 `unsafe.budget`，当前 **81/81**（**只减不增**）。
- 每个 `unsafe {}` 必须紧邻 `// SAFETY:`；每个 `unsafe fn` 必须有 `# Safety`；
  `cargo xtask gate unsafe` 做配平与预算检查。
- 新增 unsafe 必须在 `unsafe.budget` 与提交信息里写明"为什么无法避免"。
- `board-support` 与 `firmware` 是仅有的允许接触寄存器的实现层；纯逻辑 crate
  `forbid(unsafe_code)`。

## 2. 危险操作的 fail-closed

- Flash 写入：范围/对齐/只读校验 + 4 字节寻址别名自检；不确定就拒绝（`Rejected`），不静默继续。
- 启动头运行期只读；写坏只能 BOOT_MODE + 串口下载器恢复。
- 升级路径：普通升级只写备份槽，不搬运行槽；中途掉电不得破坏可启动映像。
- 未知必须隔离成没有默认值的类型（协议字段、设备状态），漏填在编译期暴露。

## 3. 安全相关输出与健康门控

- 健康位全集才允许喂狗（`primitives::safety::all_healthy` / `HealthBits`）；
  必需健康位由固件 `REQUIRED_HEALTH_BITS` 聚合。
- 失联优先的"与"判据；安全状态只能由重新上电/显式维护离开，不自动恢复。
- 连续多次复位进入安全状态并留可解释记录（`SafetySupervisor` + `fault-decode`）。
