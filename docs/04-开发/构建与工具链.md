# 构建与工具链

> capsule 视角：业务 capsule 与底座一起编译成**整包固件**；不做运行期加载/热替换。
> 仓库外业务 crate 的依赖、feature 与离线可构建性，必须在接入前按本文口径核对。
> 见 [ADR-0008](../adr/0008-静态capsule化内核.md)。

## 版本与工具链策略

| 项 | 值 | 说明 |
|----|----|------|
| rustc | **跟随最新 stable**（测量快照：`1.99.1 (58cf8f9c3 2026-10-13)`） | `rust-toolchain.toml` 只写 `channel = "stable"`，**不锁具体版本** |
| edition | **2024** | `imxrt-hal` 0.6 自身也是 2024，生态一致 |
| 目标 | `thumbv7em-none-eabihf` | Cortex-M7，单精度 FPU |
| 最低版本（MSRV） | **1.99** | `rust-version` 字段；低于它构建直接失败 |

**工具链策略：永远跟随最新 stable，不锁定具体版本。** 这是刻意的选择：

- `rust-toolchain.toml` 只声明通道与组件（`rustfmt`/`clippy`/`llvm-tools-preview`）和目标；
- **没有 `toolchain.lock`，也没有"逐字比对 rustc 版本"的门禁**（原 `check-toolchain`
  已随该策略删除）。钉死具体版本会让所有开发机与 CI 在升级时一起卡住，也让离线/内网
  环境必须预装那个精确版本；
- 可复现性改由 **入库的 `Cargo.lock` 与 `xtask/Cargo.lock`** 保证：同一份锁文件在
  任何 stable 上解析出同一组依赖版本；
- CI 镜像使用 `rust:stable`，不固定小版本；
- 新 stable 带来的新 lint 按**修代码**处理，不放宽 lint（最近一次是 1.99 的 clippy）。

当前开发机上的 `1.99.1` 只是**测量快照**，不是锁定值；文档里的版本号数字会随 stable 前进。

**工作区规模**：**20 个成员 crate**（其中 **18 个纯逻辑**，可在主机上测试）
+ `xtask`（非成员：它是主机专用工具，独立工作区，经 `cargo xtask` 别名调用）。
纯逻辑名单的唯一来源是 `xtask/src/main.rs` 的 `PURE_CRATES`（`cargo xtask pure-crates` 可打印）。

## 两个"文本真源"（都在仓库根，构建期注入）

| 文件 | 谁读它 | 规则 |
|---|---|---|
| [`VERSION`](../../VERSION) | `crates/firmware/build.rs` → `BASE_VERSION*` 环境变量 | 版本号唯一真源；格式在构建期校验，非法即构建失败 |
| [`banner.txt`](../../banner.txt) | 同上 → `OUT_DIR/banner.txt` → `main.rs` 的 `include_str!` | **启动横幅的图形**，当前字体为 **ANSI Shadow**（figlet 字体）；支持 `{version}` 占位符；非空、不含空行、≤ 64 行、≤ 4 KiB，超限即构建失败 |

两者的意图相同：**改文本文件即改行为，不必改代码**；`build.rs` 对这两个文件都
`rerun-if-changed`，所以编辑后 `cargo build` 会自动重新构建并注入。
横幅里"身份与板级事实行"（`tessera`/版本/`MCU :`/`store :`/…）由固件打印，
不随图形文件变化 —— 它们是脚本契约（`make bytecheck` 依赖）。

## 关键依赖（及其"为什么是这个名字"）

| crate | feature | 说明 |
|-------|---------|------|
| `imxrt-ral` 0.6 | `imxrt1021` + **`rt`** | RAL 按**精确型号**命名。`rt` 必须开：它带来 `device.x`（中断弱别名）与 `__INTERRUPTS` 矢量表 |
| `imxrt-hal` 0.6 | `imxrt1020` | HAL 按**家族**命名（1020 覆盖 1021），并转发 feature 给 `imxrt-iomuxc` |
| `imxrt-rt` 0.1 | **`device`** | 必须开：否则生成的链接脚本不会 `INCLUDE device.x`，链接期报一堆 `undefined symbol: LPUART2` |
| `imxrt-boot-gen` 0.4 | — | 构造 FCB（512 字节配置块） |
| `rtic` 2.3 | `thumbv7-backend` | Cortex-M7 属 ARMv7-M；换芯片只改这一处 |
| `cortex-m` 0.7 | `critical-section-single-core` | 单核临界区实现（`critical-section` 1.2） |
| `heapless` 0.9 | — | 固定容量容器（零分配） |
| `miniz_oxide` 0.9 | `default-features = false` | DEFLATE（RFC 1951）：`gzip` 的解压路径；压缩侧另开 `with-alloc`（走固定块静态池） |
| `static_assertions` 1.1 | — | 把预算/布局/尺寸一致性变成**编译失败**（`primitives`/`realtime`/`gzip`） |

⚠️ **两个 feature 命名口径不同**（RAL 精确型号 / HAL 家族），只开一个会得到
"没有外设"或"没有焊盘"的构建。

## 三个踩过的坑（写下来以免重犯）

### 1. 链接脚本用 `imxrt-link.x`，不是 `link.x`

```toml
[build]
target = "thumbv7em-none-eabihf"

[target.thumbv7em-none-eabihf]
rustflags = ["-C", "link-arg=-Timxrt-link.x"]
```

`imxrt-rt` 生成的 `imxrt-link.x` 自带 `MEMORY` 块，**因此不需要用户写 `memory.x`**。
用 cortex-m-rt 的 `link.x` 会报 `cannot find linker script memory.x`。

### 2. `rustflags` 必须挂在 `[target...]` 而不是 `[build]`

挂在 `[build]` 下会让**主机测试的链接**也带上 `-Timxrt-link.x`，于是
`cargo test` 报 `cannot find linker script imxrt-link.x`。这个坑很隐蔽：
固件能编，只有测试挂。

### 3. RTIC 需要显式强制链接两个 crate

```rust
use cortex_m_rt as _;
use imxrt_rt as _;
```

缺了会得到 `symbol not found: DefaultHandler_` 或 `undefined symbol: __pre_init` ——
错误信息不会指向"忘了 use"。⚠️ 但**不要自己定义 `DefaultHandler_`**：
`cortex-m-rt` 在强制链接后已经提供它，自定义会 duplicate symbol。

RTIC 的 device 垫片见 `crates/firmware/src/device.rs`，那里还记录了
`interrupt` 必须是**类型别名式再导出**（写成 `pub mod interrupt { pub use Interrupt; }`
会让 RTIC 报出指向"Cargo feature 没开"的**误导性**错误）。

## 常用命令

```bash
make build      # 编译 release 固件（默认目标就是固件目标）
make test       # 主机测试（纯逻辑层，显式 --target x86_64-unknown-linux-gnu）
make verify     # 全量离线验证（唯一入口，内部走 cargo xtask verify）
make gates      # 17 项静态门禁的汇总表（不因第一个失败而中断）
make image      # 对链接后的 ELF 断言 FCB/IVT/向量表
make gaps       # 列出未实现项
cargo xtask context   # 机器可读的项目上下文（JSON，供 Agent/脚本取数）
```

## 环境变量（前缀 `BASE_`）

| 变量 | 作用 |
|------|------|
| `BASE_SERIAL` | `cargo xtask bench` 抓包用的串口节点（默认 `/dev/pudu-debugger-16p-uart`） |
| `BASE_PYTHON` | 指定 xtask 调用脚本时使用的 Python 解释器（默认找 venv） |

> 台架脚本自己的覆盖变量是 `PYOCD` / `PYOCD_PY` / `UART_ALIAS`（见
> [`台架准备与排障`](台架准备与排障.md)），与上面的 `BASE_*` 互不冲突。

## 离线可构建性

本工程的依赖**全部可以离线构建**（本机 cargo 缓存已含完整闭包）。同时注意
**缓存里没有、也刻意不引入的东西**：`defmt` 全系、`panic-*`、`embedded-test`、
`proptest`、`trybuild`、`probe-rs` —— `Cargo.lock` 里一个都没有。因此：

- 日志不用 `defmt`（改用 `log`：16 B 定长记录 + 环形缓冲 + LZ4/gzip 落盘路径）；
- 属性测试用自研确定性 PRNG（`primitives::prng`），不引第三方；
- 编译失败测试用 `cargo xtask check-compile-fail` 自己跑 cargo，不引 `trybuild`；
- 目标端测试暂用"自建串口帧协议 + 主机侧校验"，`embedded-test` 作为有网时的可选项。

这些不是妥协的借口，而是**减少需要论证的工具面**——与功能安全的目标一致。
